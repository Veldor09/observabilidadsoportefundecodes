Instalación del Backend Fundecodes Digital en Windows

Este artículo describe el proceso completo para desplegar el backend del sistema Fundecodes Digital en un entorno Windows. El backend es una API REST desarrollada con NestJS, con PostgreSQL como base de datos y Prisma como ORM. El proceso utiliza Docker Desktop para levantar la base de datos y PowerShell para ejecutar el servidor.

1. Descripción del sistema

Fundecodes Digital es la plataforma de gestión interna de la fundación. El backend expone una API REST que cubre los siguientes módulos:

  • Autenticación JWT (login, recuperación de contraseña)
  • Gestión de usuarios, roles y permisos
  • Proyectos y programa de voluntariado
  • Facturación, contabilidad y reportes
  • Noticias y páginas informativas
  • Endpoint /metrics para Prometheus

3. Instalar Node.js en Windows

  1. Descargar el instalador LTS desde nodejs.org (archivo .msi para Windows 64-bit).
  2. Ejecutar el instalador con las opciones por defecto. Si aparece la pantalla "Tools for Native Modules", marcar la casilla para instalar las herramientas adicionales.
  3. Abrir una nueva ventana de PowerShell y verificar: 
    node --version   # v20.x.x
npm --version    # 10.x.x

[IMAGEN: Instalador de Node.js en Windows mostrando la pantalla con la versión 20.x LTS y las opciones de instalación seleccionadas]

4. Instalar Docker Desktop en Windows

  1. Descargar Docker Desktop desde docker.com/products/docker-desktop.
  2. Ejecutar el instalador. Seleccionar la opción de usar WSL 2 como backend (recomendado en Windows 10/11).
  3. Reiniciar el equipo si el instalador lo solicita.
  4. Abrir Docker Desktop y esperar a que el ícono de la ballena en la barra de tareas indique que Docker está corriendo.
  5. Verificar en PowerShell: 
    docker --version
docker compose version

[IMAGEN: Docker Desktop en Windows con el ícono en la barra de tareas y el panel principal mostrando que el motor está corriendo (Engine running)]

5. Obtener el código fuente

Abrir PowerShell y ejecutar:

# Clonar el repositorio
git clone <URL_DEL_REPOSITORIO> fundecodes
cd fundecodes\Back\backfundecodesdigital

La estructura relevante del proyecto es la siguiente:

Back\backfundecodesdigital\
├── src\                    # Código fuente NestJS
│   ├── metrics\            # Métricas Prometheus
│   ├── webhooks\           # Integración ServiceNow y Teams
│   ├── auth\               # Autenticación JWT
│   └── SistemaAdmin\       # Módulos del sistema
├── prisma\
│   ├── schema.prisma       # Modelo de base de datos
│   └── migrations\         # Migraciones aplicadas
├── docker-compose.yml      # PostgreSQL en contenedor
├── Dockerfile              # Imagen de producción
└── .env.production.example # Plantilla de variables de entorno

6. Configurar variables de entorno

Copiar la plantilla de ejemplo y editarla:

# En PowerShell, desde la carpeta backfundecodesdigital\
Copy-Item .env.production.example .env
notepad .env

Las variables mínimas necesarias para desarrollo local son:

NODE_ENV=development
PORT=4000

# PostgreSQL (debe coincidir con docker-compose.yml)
DATABASE_URL=postgresql://fundecodes:fundecodes@localhost:5432/fundecodes_db?schema=public

# JWT — generar con: node -e "console.log(require('crypto').randomBytes(48).toString('base64'))"
JWT_SECRET=REEMPLAZAR_CON_SECRETO_LARGO
JWT_EXPIRES=1d

# Correo (opcional para desarrollo local)
MJ_APIKEY_PUBLIC=
MJ_APIKEY_PRIVATE=

# ServiceNow (para integración de alertas)
SERVICENOW_INSTANCE=https://<tu-instancia>.service-now.com
SERVICENOW_USER=api.fundecodes
SERVICENOW_PASSWORD=<contraseña>

# MS Teams (Webhook de Power Automate)
TEAMS_WEBHOOK_URL=https://<tu-webhook>

7. Levantar la base de datos con Docker Desktop

Desde PowerShell en la carpeta backfundecodesdigital\:

docker compose up -d

Verificar que el contenedor está corriendo:

docker compose ps

La salida esperada es:

NAME           IMAGE         STATUS          PORTS
fundecodes-db  postgres:16   Up (healthy)    0.0.0.0:5432->5432/tcp

También se puede verificar visualmente en el panel de Docker Desktop: el contenedor fundecodes-db debe aparecer con estado Running (ícono verde).

[IMAGEN: Docker Desktop en Windows mostrando el contenedor fundecodes-db en estado Running con el puerto 5432 mapeado]

8. Instalar dependencias Node.js y ejecutar migraciones

# Instalar dependencias
npm install

# Generar el cliente Prisma
npx prisma generate

# Aplicar las migraciones a la base de datos
npx prisma migrate deploy

# (Opcional) Poblar datos iniciales
npx prisma db seed

[IMAGEN: PowerShell mostrando la salida de npx prisma migrate deploy con todas las migraciones aplicadas exitosamente]

9. Iniciar el backend

Modo desarrollo (con hot-reload)

npm run start:dev

Modo producción

npm run build
npm run start:prod

Una vez iniciado, el backend estará disponible en http://localhost:4000.

10. Verificar el funcionamiento desde PowerShell

# Verificar health check
Invoke-WebRequest -Uri http://localhost:4000/healthz | Select-Object -ExpandProperty Content

# Verificar métricas Prometheus (primeras 20 líneas)
(Invoke-WebRequest -Uri http://localhost:4000/metrics).Content -split "`n" | Select-Object -First 20

La respuesta de /healthz debe contener {"status":"ok"}. La respuesta de /metrics debe mostrar líneas con prefijos como http_requests_total y nodejs_heap_size_used_bytes.

11. Resolución de problemas comunes en Windows

SíntomaCausa probableSolución
Error: Can't reach database server at localhost:5432 Docker Desktop no está corriendo o el contenedor no levantó Abrir Docker Desktop, esperar a que el motor inicie, luego docker compose up -d
Error de política de ejecución de scripts en PowerShell Windows bloquea scripts por defecto Ejecutar en PowerShell como administrador: Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
Puerto 4000 ya en uso Otro proceso ocupa el puerto Cambiar PORT=4001 en .env o identificar el proceso: netstat -ano | findstr :4000
Métricas no aparecen en Prometheus Prometheus apunta a dirección incorrecta Verificar que prometheus.yml usa host.docker.internal:4000 (no localhost) ya que Prometheus corre dentro de Docker
Error CORS desde el frontend CORS_ALLOWED_ORIGINS no incluye el origen del frontend Agregar http://localhost:3000 a CORS_ALLOWED_ORIGINS en el .env del backend
npx prisma migrate deploy falla con error de conexión El contenedor de PostgreSQL no está listo aún Esperar 10-15 segundos después de docker compose up -d y volver a intentar
