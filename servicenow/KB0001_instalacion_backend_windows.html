Instalación del Backend Fundecodes Digital en Windows

Este artículo describe el proceso completo para desplegar el backend del sistema Fundecodes Digital en un entorno Windows. El backend es una API REST desarrollada con NestJS, con PostgreSQL como base de datos y Prisma como ORM. El proceso utiliza Docker Desktop para levantar la base de datos en un contenedor aislado y PowerShell para ejecutar el servidor.

1. Descripción del sistema

Fundecodes Digital es la plataforma de gestión interna de la fundación ambiental. El backend expone una API REST que cubre los siguientes módulos:

  • Autenticación JWT (login, recuperación de contraseña)
  • Gestión de usuarios, roles y permisos
  • Proyectos y programa de voluntariado
  • Facturación, contabilidad y reportes
  • Noticias y páginas informativas
  • Endpoint GET /metrics para Prometheus (prom-client)
  • Endpoint POST /api/webhooks/alert para integración con Grafana → ServiceNow → MS Teams

Stack tecnológico:

  • NestJS — Framework Node.js
  • Prisma ORM — Gestión de base de datos y migraciones
  • PostgreSQL 16 — Base de datos relacional (en Docker)
  • prom-client — Métricas para Prometheus
  • Puerto por defecto: 4001

4. Instalar Node.js en Windows

  1. Descargar el instalador LTS desde https://nodejs.org/en/download (archivo .msi para Windows 64-bit).
  2. Ejecutar el instalador con las opciones por defecto. Si aparece la pantalla "Tools for Native Modules", marcar la casilla para instalar las herramientas adicionales.
  3. Abrir una nueva ventana de PowerShell y verificar: 
    node --version   # debe mostrar v20.x.x o superior
npm --version    # debe mostrar 10.x.x o superior

[IMAGEN: Instalador de Node.js en Windows mostrando la pantalla de bienvenida con versión 20.x LTS]

5. Instalar Docker Desktop en Windows

  1. Descargar Docker Desktop desde https://www.docker.com/products/docker-desktop.
  2. Ejecutar el instalador. Seleccionar la opción de usar WSL 2 como backend (recomendado en Windows 10/11).
  3. Reiniciar el equipo si el instalador lo solicita.
  4. Abrir Docker Desktop y esperar a que el ícono de la ballena en la barra de tareas muestre que Docker está corriendo (Engine running).
  5. Verificar en PowerShell: 
    docker --version
docker compose version

[IMAGEN: Docker Desktop en Windows mostrando el panel principal con Engine running (ícono verde)]

6. Obtener el código fuente

Abrir PowerShell como usuario normal (no como administrador) y ejecutar:

# Clonar el repositorio del backend
git clone https://github.com/Veldor09/backproyectosoportefundecodes

# Entrar a la carpeta del proyecto
cd backproyectosoportefundecodes

La estructura relevante del proyecto es la siguiente:

backproyectosoportefundecodes\
├── src\                    # Código fuente NestJS
│   ├── metrics\            # Métricas Prometheus (prom-client)
│   ├── webhooks\           # Integración ServiceNow y Teams
│   ├── auth\               # Autenticación JWT
│   └── SistemaAdmin\       # Módulos del sistema
├── prisma\
│   ├── schema.prisma       # Modelo de base de datos
│   └── migrations\         # Migraciones (22 migraciones aplicadas)
├── docker-compose.yml      # PostgreSQL en contenedor aislado (puerto 5434)
└── .env.example            # Plantilla de variables de entorno

7. Configurar variables de entorno

Copiar la plantilla de ejemplo y editarla:

# Desde PowerShell, en la raíz del proyecto clonado
Copy-Item .env.example .env
notepad .env

El archivo .env debe contener como mínimo:

# ─── Postgres LOCAL ───────────────────────────────────────────────
DATABASE_URL="postgresql://fundecodes_soporte:fundecodes_soporte@localhost:5434/fundecodes_soporte?schema=public"
DIRECT_URL="postgresql://fundecodes_soporte:fundecodes_soporte@localhost:5434/fundecodes_soporte?schema=public"

# ─── App ──────────────────────────────────────────────────────────
PORT=4001
NODE_ENV=development

FRONTEND_URL=http://localhost:3000
PUBLIC_FRONTEND_URL=http://localhost:3000
FRONTEND_SET_PASSWORD_PATH=/set-password
FRONTEND_RESET_PASSWORD_PATH=/reset-password

# ─── JWT — generar con: node -e "console.log(require('crypto').randomBytes(48).toString('base64'))"
JWT_SECRET=REEMPLAZAR_CON_SECRETO_LARGO
PASSWORD_JWT_SECRET=REEMPLAZAR_CON_SECRETO_LARGO
PASSWORD_JWT_EXPIRES=30m
RESET_JWT_SECRET=REEMPLAZAR_CON_SECRETO_LARGO
RESET_JWT_EXPIRES=30m

# ─── ServiceNow (para integración de alertas) ─────────────────────
SERVICENOW_INSTANCE=https://<tu-instancia>.service-now.com
SERVICENOW_USER=admin
SERVICENOW_PASSWORD=<contraseña-de-la-instancia>

# ─── MS Teams (Webhook de Power Automate) ────────────────────────
TEAMS_WEBHOOK_URL=https://<tu-webhook-de-power-automate>
Importante sobre el puerto y la base de datos:
El backend corre en el puerto 4001 (no 4000) para evitar conflictos con otros servicios comunes. La base de datos PostgreSQL corre en el puerto 5434 (no 5432) para no interferir con instalaciones locales de PostgreSQL. El nombre de la base de datos es fundecodes_soporte.

8. Levantar la base de datos con Docker Desktop

Desde PowerShell en la raíz del proyecto clonado:

docker compose up -d

Verificar que el contenedor está corriendo:

docker compose ps

La salida esperada es:

NAME                      IMAGE         STATUS          PORTS
fundecodes-soporte-db     postgres:16   Up (healthy)    0.0.0.0:5434->5432/tcp

También se puede verificar visualmente en Docker Desktop: el contenedor fundecodes-soporte-db debe aparecer con estado Running (ícono verde) y mostrar el mapeo de puertos 0.0.0.0:5434→5432/tcp.

[IMAGEN: Docker Desktop mostrando el contenedor fundecodes-soporte-db en estado Running]

9. Instalar dependencias y ejecutar migraciones

# 1. Instalar dependencias de Node.js
npm install

# 2. Generar el cliente Prisma
npx prisma generate

# 3. Aplicar las 22 migraciones a la base de datos
npx prisma migrate deploy

La salida de npx prisma migrate deploy debe mostrar algo similar a:

  20240102_add_users
  ... (todas las migraciones)

11. Iniciar el backend

Modo desarrollo (con hot-reload)

npm run start:dev

Modo producción

npm run build
npm run start:prod

Una vez iniciado, el backend estará disponible en http://localhost:4001.

12. Verificar el funcionamiento desde PowerShell

# Verificar health check
Invoke-WebRequest -Uri http://localhost:4001/healthz | Select-Object -ExpandProperty Content

# Verificar métricas Prometheus (primeras 20 líneas)
(Invoke-WebRequest -Uri http://localhost:4001/metrics).Content -split "`n" | Select-Object -First 20

La respuesta de /healthz debe contener {"status":"ok"}. La respuesta de /metrics debe mostrar líneas como http_requests_total, nodejs_heap_size_used_bytes y process_cpu_seconds_total.

13. Resolución de problemas comunes en Windows

SíntomaCausa probableSolución
Error: Can't reach database server at localhost:5434 Docker Desktop no está corriendo o el contenedor no levantó Abrir Docker Desktop, esperar a que el motor inicie, luego: docker compose up -d
Error de política de ejecución en PowerShell Windows bloquea scripts por defecto Ejecutar en PowerShell como administrador: Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
Puerto 4001 ya está en uso (EADDRINUSE) Una instancia anterior del backend sigue corriendo Identificar y terminar el proceso:
netstat -ano | findstr ":4001" | findstr "LISTENING"
taskkill /PID <número_PID> /F
Métricas no aparecen en Prometheus Prometheus apunta a dirección incorrecta dentro de Docker Verificar que prometheus.yml usa host.docker.internal:4001 (no localhost) ya que Prometheus corre dentro de Docker
Error CORS desde el frontend FRONTEND_URL no incluye el origen del frontend Asegurarse de que en el .env del backend: FRONTEND_URL=http://localhost:3000
npx prisma migrate deploy falla con error de conexión El contenedor de PostgreSQL no está listo aún Esperar 10-15 segundos después de docker compose up -d y volver a intentar
