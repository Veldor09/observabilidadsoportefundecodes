Instalación del Frontend Fundecodes Digital en Windows

Este artículo describe el proceso para instalar y ejecutar el frontend del sistema Fundecodes Digital en Windows. El frontend es una aplicación web desarrollada con Next.js 14 y Tailwind CSS. Se conecta al backend NestJS a través de su API REST.

1. Descripción del sistema

El frontend provee la interfaz de usuario para todos los módulos del sistema Fundecodes: panel administrativo, gestión de proyectos, voluntariado, facturación, contabilidad y reportes.

Stack tecnológico:

  • Next.js 14 — Framework React con renderizado del lado del servidor (SSR) y App Router
  • Tailwind CSS — Framework de estilos utilitario
  • Node.js 20 — Runtime de JavaScript (requerido)
  • Puerto por defecto: 3000

4. Instalar Node.js en Windows

  1. Descargar el instalador LTS desde https://nodejs.org/en/download (archivo .msi para Windows 64-bit).
  2. Ejecutar el instalador. Marcar la opción "Automatically install the necessary tools" si se solicita.
  3. Al finalizar, abrir una nueva ventana de PowerShell y verificar: 
    node --version   # v20.x.x
npm --version    # 10.x.x

[IMAGEN: Instalador de Node.js en Windows mostrando la pantalla de selección de versión 20.x LTS]

5. Obtener el código fuente

Abrir PowerShell o Git Bash y ejecutar: 

# Clonar el repositorio del frontend
git clone https://github.com/Veldor09/frontproyectosoportefundecodes

# Entrar a la carpeta del proyecto
cd frontproyectosoportefundecodes

La estructura del frontend es la siguiente:

frontproyectosoportefundecodes/
├── src/
│   └── app/                # Rutas y páginas Next.js (App Router)
│       ├── admin/          # Panel de administración
│       ├── auth/           # Páginas de autenticación
│       ├── proyectos/      # Módulo de proyectos
│       ├── voluntarios/    # Módulo de voluntariado
│       └── facturacion/    # Módulo de facturación
├── public/                 # Archivos estáticos (íconos, imágenes)
├── next.config.mjs         # Configuración de Next.js
├── tailwind.config.js      # Configuración de Tailwind CSS
└── package.json            # Dependencias

[IMAGEN: PowerShell mostrando la salida del git clone y la estructura de carpetas del proyecto frontend]

6. Configurar variables de entorno

Crear el archivo .env.local en la raíz del proyecto clonado: 

# En PowerShell, desde la carpeta frontproyectosoportefundecodes/
notepad .env.local

Agregar el siguiente contenido:

# URL del backend NestJS — IMPORTANTE: usar puerto 4001
NEXT_PUBLIC_API_URL=http://localhost:4001

# (Opcional) Nombre de la aplicación
NEXT_PUBLIC_APP_NAME=Fundecodes Digital
Advertencia: Si se escribe localhost:4000 en lugar de localhost:4001, el frontend no podrá comunicarse con el backend y mostrará errores de red en todas las páginas. Siempre verificar este valor.
Importante: El archivo .env.local no se sube a Git (está en .gitignore). Cada desarrollador debe crearlo manualmente en su equipo. Si se modifica este archivo, es necesario reiniciar el servidor (npm run dev) para que los cambios tengan efecto.

[IMAGEN: Bloc de notas o VS Code con el archivo .env.local abierto mostrando NEXT_PUBLIC_API_URL=http://localhost:4001]

7. Instalar dependencias

Desde la raíz del proyecto en PowerShell:

npm install

Este proceso puede tardar entre 1 y 3 minutos dependiendo de la velocidad de la conexión a internet. Al finalizar debe mostrar un mensaje similar a: 

added 312 packages, and audited 313 packages in 45s

[IMAGEN: PowerShell mostrando la salida de npm install completada exitosamente con el número de paquetes instalados]

8. Iniciar el servidor de desarrollo

npm run dev

La salida esperada es:

Abrir un navegador web y visitar http://localhost:3000.

9. Build de producción (opcional)

Para generar una build optimizada para producción:

# Generar build de producción
npm run build

# Iniciar el servidor de producción
npm run start

El servidor de producción también estará disponible en http://localhost:3000 pero con el código compilado y optimizado.

10. Verificar la conexión con el backend

Para confirmar que el frontend se comunica correctamente con el backend:

  1. Asegurarse de que el backend esté corriendo en http://localhost:4001 (ver KB0001).
  2. Abrir el panel de administración en http://localhost:3000/admin.
  3. Abrir las herramientas de desarrollador del navegador (F12) → pestaña Network.
  4. Recargar la página y verificar que las peticiones a localhost:4001 retornen códigos HTTP 200 o 401 (no errores de red como ERR_CONNECTION_REFUSED).

[IMAGEN: DevTools del navegador mostrando la pestaña Network con peticiones exitosas al backend en localhost:4001]

11. Resolución de problemas comunes en Windows

SíntomaCausa probableSolución
npm : El término 'npm' no se reconoce Node.js no está instalado o no está en el PATH Reinstalar Node.js y abrir una nueva ventana de PowerShell
Error de política de ejecución de scripts en PowerShell Windows bloquea scripts por defecto Ejecutar como administrador: Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
Puerto 3000 en uso Otro proceso ocupa el puerto Ejecutar npm run dev -- -p 3001 para usar otro puerto, y actualizar FRONTEND_URL en el .env del backend
Error Network Error o ERR_CONNECTION_REFUSED al usar el sistema El backend no está corriendo o NEXT_PUBLIC_API_URL apunta al puerto incorrecto 1. Iniciar el backend (ver KB0001).
2. Verificar que .env.local tiene NEXT_PUBLIC_API_URL=http://localhost:4001.
3. Reiniciar el servidor de Next.js.
Páginas en blanco o sin datos después de login Variable NEXT_PUBLIC_API_URL incorrecta o ausente Verificar el archivo .env.local y reiniciar: npm run dev
Error de CORS al llamar al backend El backend no permite el origen del frontend Verificar que en el .env del backend: FRONTEND_URL=http://localhost:3000
Cambios en .env.local no surten efecto Las variables de entorno se cargan solo al iniciar Next.js Detener el servidor con Ctrl+C y volver a ejecutar npm run dev
